# 音乐打碟

右键企鹅 → 陪伴 → **音乐打碟 · 双彩灯**，只保留一个开关，默认开启。

开启后自动跟随电脑默认播放设备的实际声音，播放器和浏览器使用相同方式。旧版「自动识别音乐」和「音频跟随（含浏览器）」设置都会自动迁移到这一方式；原先关闭的保持关闭。关闭开关会停止音频采集。持续人声、视频和游戏声音也可能触发。

关闭控制面板后开始律动；暂停/静音后，企鹅平滑返回待机。隐藏、自动半隐藏、全屏隐藏、安静陪伴、系统或应用减少动态、安全模式均暂停音乐场景并释放采集。拖拽、下落、点击动作和 Codex 工作、待确认、完成或错误反馈优先于打碟。音频设备暂不可用时显示原因，并自动重试；接入耳机或切换默认播放设备后重建采集。

## 动作与灯光

使用用户提供的 DJ2 原视频，固定比例和脚线，清理背景后增加短 RIFE 循环闭合片段，提供透明 WebM 与 24fps PNG 回退。不重绘企鹅；DJ1 留作原始备用素材，未作为另一种皮肤显示。灯条独立绘制，低频/高频能量控制左右高度，检测到的起音控制亮度，颜色连续渐变。

节拍估计基于 10ms 音频能量变化、短窗口自相关和置信度，80–180 BPM 的规律测试节拍覆盖基本范围。无稳定节拍时维持原速；有可信节拍时在 0.8–1.25 倍范围内平滑调整整段视频，极端速度采用半拍/双拍映射。真实歌曲可能有半拍/双拍歧义。视频中的搓盘动作并非严格等拍，整体调速不保证每个手势精确落拍。

## 本地数据边界

仅使用 Windows 播放端 WASAPI loopback，不使用麦克风。不保存或上传音频，不读取歌曲标题。当前直接分析默认播放设备混音，混入的其他声音也会影响灯条。无需播放器上报媒体类型或匹配应用名单。尚未实现逐进程音频隔离或语义音乐分类。

## 验证

```powershell
npm.cmd run build
npm.cmd test
cargo test --manifest-path src-tauri/Cargo.toml --lib
cargo clippy --manifest-path src-tauri/Cargo.toml --lib -- -D warnings
```

显式实机测试（需在同一 Windows 会话播放音频，默认测试不执行）：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib live_output_probe -- --ignored --nocapture
```

隔离的原生场景验收可使用 `--smoke --smoke-preview --smoke-music`；它使用独立状态目录并开启音乐律动，且只在这个显式预览内忽略系统减少动态。再加 `--smoke-music-simulated` 仅验证模拟拍点下的视频和灯条，不作为真实采集证据。普通启动不会生成模拟音乐。
